# ฟิตตามคลิป

เว็บคำนวณแคลอรี่จากคลิปออกกำลังกาย จดอาหาร และแจ้งเตือนตารางผ่าน LINE

## ฟังก์ชันหลัก

- **ให้คะแนนและวิเคราะห์ความสมดุลของตาราง** (Workout Schedule Score 0–100 แยก 5 ด้าน) พร้อม AI สรุปและแนะนำ
- **ปรับตารางอัตโนมัติเมื่อข้ามวัน** ด้วยการค้นหาวันที่ดีที่สุด (optimization) เฉพาะสัปดาห์นั้น
- **"อยากออกส่วนไหนวันนี้"** จัดท่า เซต จำนวนครั้ง และเวลาพัก ตามระดับ เป้าหมาย อุปกรณ์ และเวลาที่มี
- **หน้า "วันนี้"** บอกว่าวันนี้ต้องออกอะไร ปุ่มทำสำเร็จ/ข้าม และ streak
- **ความก้าวหน้า** บันทึกน้ำหนัก/รอบเอวรายสัปดาห์ กราฟ ตารางสรุป และ AI วิเคราะห์แนวโน้ม
- **วิเคราะห์คลิป YouTube** แยกช่วง แคลอรี่ ระดับความหนัก (เบา/ปานกลาง/หนัก) และกล้ามเนื้อที่ใช้
- คำนวณแคลอรี่ต่อวันตาม 6 เป้าหมาย, ประเมินแคลอรี่อาหารด้วย AI, แจ้งเตือนผ่าน LINE

## หลักการทำงาน (ใช้อ้างอิงในรายงานโครงงานได้)

แนวคิดหลักคือ **ตัวเลขทุกตัวคำนวณด้วยกฎในโค้ด ส่วน AI ใช้แปลงผลเป็นภาษาคน** ผลจึงคงที่ ตรวจสอบได้ และอธิบายที่มาได้

### คะแนนตาราง (`analysis.py`)

| ด้าน | น้ำหนัก | ตรวจอะไร |
|---|---|---|
| ความสมดุลกล้ามเนื้อ | 25% | ความถี่ส่วนล่าง/ส่วนบน/แกนกลาง, ส่วนล่างกับส่วนบนต่างกัน ≥ 2 ครั้ง, อกกับหลัง, กล้ามเนื้อเดิมถูกฝึกถี่เกินไป |
| วันพักและการฟื้นตัว | 20% | จำนวนวันพักเทียบช่วงที่เหมาะกับระดับ, วันออกกำลังกายต่อเนื่องยาวเกิน |
| ความหนัก | 20% | จำนวนวันหนักเทียบเพดานของระดับ, วันหนักติดกัน |
| ความเหมาะสมกับเป้าหมาย | 20% | นาทีคาร์ดิโอและวันฝึกกล้ามเนื้อเทียบเป้าหมายของแต่ละเป้า |
| ระยะเวลารวม | 15% | นาทีต่อสัปดาห์เทียบช่วงของระดับ, วันที่ยาวเกิน |

ระดับผู้ใช้เป็นข้อจำกัด (constraint) เช่น ผู้เริ่มต้นต้องพักกล้ามเนื้อเดิม ≥ 2 วัน (72 ชม.) และมีวันหนักไม่เกิน 2 วัน
ส่วนระดับกลาง/สูงพัก ≥ 1 วัน (48 ชม.) ค่าทั้งหมดอยู่ใน `LEVEL_RULES` และ `GOAL_RULES` ปรับได้

### ปรับตารางอัตโนมัติ (`optimizer.py`)

- ตัวแปรตัดสินใจ: วันปลายทางที่จะย้าย session ที่ข้ามไป หรือไม่ชดเชย
- ฟังก์ชันเป้าหมาย: คะแนนตารางของสัปดาห์นั้น
- ข้อจำกัด: ต้องเหลือวันพักตามแผน ≥ 1 วัน, วันปลายทางต้องไม่ยาวเกินเพดานของระดับ, ย้ายได้เฉพาะวันที่ยังมาไม่ถึง
- วิธี: ค้นหาครบทุกทางเลือก (มีไม่เกิน 7) จึงได้คำตอบที่ดีที่สุดแน่นอน ถ้าย้ายแล้วไม่ดีกว่าไม่ชดเชย ระบบจะแนะนำให้ข้าม
- การย้ายมีผลเฉพาะสัปดาห์นั้น ตารางหลักไม่เปลี่ยน

### จัดท่าให้ (`exercises.py`)

เลือกท่าแบบ greedy ให้ครอบคลุมกล้ามเนื้อเป้าหมายมากที่สุด เน้นท่าใหญ่ก่อน ไม่ซ้ำแนวการเคลื่อนไหว
และกรองตามระดับและอุปกรณ์ จำนวนเซต/ครั้ง/เวลาพักอิงช่วงทั่วไปของแต่ละเป้าหมาย
(แข็งแรง 5–8 ครั้ง พักนาน, กล้ามโต 8–12 ครั้ง, ลดน้ำหนัก/ฟิต 12–15 ครั้งแบบวงจรพักสั้น)
แล้วตัดให้พอดีเวลาที่ผู้ใช้มี ถ้ากล้ามเนื้อกลุ่มเดียวกันเพิ่งฝึกภายใน 48 ชม. ระบบจะเตือน

## รันในเครื่อง (ยังไม่ต้องตั้งค่า LINE)

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
cp .env.example .env               # แล้วแก้ DEV_LOGIN=1
uvicorn app.main:app --reload
```

เปิด http://localhost:8000 แล้วกด "เข้าแบบทดสอบ (ไม่ผ่าน LINE)"
ถ้ายังไม่ใส่ `GEMINI_API_KEY` ระบบจะให้กรอกแคลอรี่เอง

รันเทสต์: `pytest -q` (ต้องผ่านครบ 128 ข้อ)

## ตั้งค่า LINE

ทำใน https://developers.line.biz/console/

1. สร้าง **Provider** หนึ่งตัว
2. ใน Provider นั้น สร้าง **Messaging API channel** (คือ LINE Official Account ที่จะส่งแจ้งเตือน)
   แท็บ Messaging API → ออก **Channel access token (long-lived)** → ใส่ใน `LINE_MESSAGING_TOKEN`
3. ใน **Provider เดียวกัน** สร้าง **LINE Login channel** (ประเภทแอป: Web app)
   - แท็บ Basic settings: เอา Channel ID / Channel secret ใส่ `LINE_LOGIN_CHANNEL_ID` / `LINE_LOGIN_CHANNEL_SECRET`
   - แท็บ LINE Login: ตั้ง Callback URL = `https://<ชื่อแอป>.onrender.com/auth/line/callback`
   - แท็บ Basic settings: ช่อง Linked LINE Official Account เลือก OA จากข้อ 2 (ทำให้ตอน login มีหน้าชวนแอดเพื่อน)

สำคัญ:
- ทั้งสอง channel **ต้องอยู่ใต้ Provider เดียวกัน** ไม่งั้น userId ที่ได้จาก login จะใช้ส่งข้อความไม่ได้
- LINE Login channel ที่ยังเป็นสถานะ Developing ใช้ได้เฉพาะ admin/tester ของ channel
  ถ้าจะให้คนอื่นใช้ ต้องกด Publish
- ผู้ใช้ต้องแอด OA เป็นเพื่อนก่อน ถึงจะได้รับข้อความ

## ฐานข้อมูล

สมัคร Neon (https://neon.tech) หรือ Supabase สร้างโปรเจกต์ แล้วคัดลอก connection string

## Gemini API

ขอ API key ที่ https://aistudio.google.com แล้วใส่ใน `GEMINI_API_KEY`
ถ้าชื่อโมเดลใน `GEMINI_MODEL` เลิกให้บริการ ให้เปลี่ยนเป็นรุ่น Flash ที่ใหม่กว่าตามหน้าเอกสารของ Google

### วิเคราะห์คลิปทำงานยังไง

1. แปลงลิงก์ทุกรูปแบบ (youtu.be, shorts, watch?v=...) เป็นลิงก์มาตรฐาน คลิปเดียวกันจึงวิเคราะห์ครั้งเดียว
2. เช็กว่าคลิปเปิดสาธารณะผ่าน YouTube oEmbed ก่อน จะได้ไม่เสียค่า Gemini กับคลิปที่เปิดไม่ได้
3. ส่งลิงก์ให้ Gemini ดูคลิป แล้วตอบเป็นช่วงๆ โดยต้องเลือกหมวดจากตารางใน `video.py` เท่านั้น
4. แคลอรี่คำนวณในโค้ด: MET × น้ำหนัก (กก.) × ชั่วโมง ของแต่ละช่วง แล้วรวมกัน

ค่า MET ใน `video.py` เป็นค่าประมาณ ปรับได้ตามต้องการ ผลวิเคราะห์ที่เก็บไว้ไม่มีน้ำหนักผู้ใช้ปนอยู่
ถ้าเปลี่ยนค่า MET หรือผู้ใช้แก้น้ำหนัก ตัวเลขจะคำนวณใหม่ทันทีโดยไม่ต้องวิเคราะห์คลิปซ้ำ

Gemini อ่านได้เฉพาะคลิปสาธารณะ และคิดค่าใช้จ่ายตามความยาวคลิป (ตั้ง `MEDIA_RESOLUTION_LOW` ไว้แล้วเพื่อลด token)
คลิปยาวมากอาจใช้เวลานานหรือเกินโควตาของแพ็กฟรี

## ขึ้น Render

1. push โค้ดขึ้น GitHub (ไฟล์ `.env` ถูก ignore ไว้แล้ว ห้าม push)
2. ใน Render เลือก New → Blueprint → เลือก repo (Render จะอ่าน `render.yaml`)
3. ใส่ Environment Variables ที่ขึ้นว่าต้องกรอก
   - `BASE_URL` = `https://<ชื่อแอป>.onrender.com` (ต้องตรงกับ Callback URL ใน LINE)
   - `SESSION_SECRET` และ `CRON_SECRET` Render สุ่มให้อัตโนมัติ
   - **ห้ามตั้ง** `DEV_LOGIN=1` บน Render
4. หลังดีพลอยเสร็จ เปิด `https://<ชื่อแอป>.onrender.com/healthz` ต้องได้ `{"ok": true}`

## ตั้ง cron-job.org สำหรับแจ้งเตือน

สร้าง cronjob ใหม่
- URL: `https://<ชื่อแอป>.onrender.com/cron/remind`
- Method: POST
- ทุก 5 นาที
- Header: `X-Cron-Secret` = ค่า `CRON_SECRET` จาก Render

ระบบจะส่งรายการของวันนี้ที่ถึงเวลาแล้วและยังไม่ได้ส่ง และรวมทุกรายการของคนเดียวกันเป็นข้อความเดียว
เพื่อประหยัดโควตาข้อความของ LINE
